# MorphDoc · 墨呈 v0.6.6

> 发布日期：2026-11-21 · 变更范围：[v0.6.5...v0.6.6](https://github.com/SkyJourney/MorphDoc/compare/v0.6.5...v0.6.6)

## 概述

本版本修复 v0.6.5 的 Docker 镜像无法启动的问题，把 Node.js 锁定为 26.13.1，并让发布流程在交付前真正启动镜像做验收。

- **修复 Docker 镜像启动失败**：v0.6.5 的镜像启动即退出。运行层补齐了 workspace 依赖（此前报 `Cannot find package 'fastify'`），Chromium 改为按服务锁定的 Playwright 版本安装（此前拉取的是未锁定的最新版，浏览器版本与服务不一致）。
- **Node.js 锁定为 26.13.1**：仓库根目录的 `.nvmrc` 为唯一来源；CI、Docker 构建与运行时、compose 默认值和文档保持一致，由契约测试守住。
- **发布前镜像启动验收**：Release 工作流在归集前启动同一个镜像，检查运行时 Node 版本、健康检查与真实 PDF 生成；验收失败则不归集、不发布。
- **CI 与发布基线升级**：CI 与发布流水线的 Node 基线升级到 26，使用的 GitHub Actions 升级到 node24 运行时，避免 Node 20 的弃用风险。

应用代码（`apps/` 与 `packages/` 中的产品代码）本版本未改动，桌面端应用代码同样未变；Web 与 Docker 的行为变化仅来自上述修复。

### 其他变更

- 容器运行时基础镜像升级到 Node 26，并修复两个既有启动缺陷 ([#15](https://github.com/SkyJourney/MorphDoc/pull/15))

<details><summary>#15 的完整说明</summary>

容器运行时基础镜像由 node:22 升级为 node:26-bookworm-slim（选项 A）。

切换过程中发现并修复两个既有缺陷（main 上的 Node 22 镜像同样存在）：
1. 依赖断链：运行层只复制根 node_modules，服务报 Cannot find package 'fastify' 无法启动。修复：收集全部 workspace 包的 node_modules 到 /app-deps 整体复制，并在构建期断言 server 的依赖可解析。
2. Chromium 版本错配：npx playwright install 在 /app 下拉取了最新版 playwright（chromium-1255），而服务锁定 1.62.0（需要 chromium-1234）。修复：改为调用 apps/server 中锁定版本的 Playwright CLI。

Node 26 官方镜像不再自带 corepack，改为按 packageManager 字段用 npm 安装同一版本的 pnpm 并校验版本。

验证（在 2c2d6c1 上）：CI 8 项、E2E、amd64 发布演练全部通过；演练 Stage 中的完整 Docker 构建使用 Node 26、执行了修复步骤、未出现 node:22；归集 8 个产物校验和一致。本机 amd64 完整镜像：服务健康，PDF 生成成功（有效 PDF、ToUnicode 映射、中文 CID 字体）；字体包门禁通过。

</details>

### 迁移说明

- **v0.6.5 的 Docker 镜像与离线部署包不可用，请勿使用。** `MorphDoc-Web-0.6.5-image.tar.gz` 启动即退出，已于 2026-11-21 从发布页删除；`MorphDoc-Web-0.6.5-deploy.zip` 的离线步骤加载的也是这份镜像，同样无法运行。请改用本版本的 `MorphDoc-Web-0.6.6-image.tar.gz` 与 `MorphDoc-Web-0.6.6-deploy.zip`。
- **离线部署**：`docker load` 后镜像名为 `morphdoc:v0.6.6`，与部署包 `.env.example` 中的 `MORPHDOC_IMAGE` 一致，按部署包内的 `OFFLINE-README.md` 执行即可。
- **源码构建**：`deploy/compose.yaml` 的默认运行时基础镜像由 `node:22-bookworm-slim` 改为 `node:26.13.1-bookworm-slim`，从源码执行 `docker compose build` 时需要能拉取该镜像。
- **本地开发**：推荐使用 `.nvmrc` 中的 Node.js 26.13.1，与 CI 和容器一致。`package.json` 的 `engines` 仍为 `>=22`，最低要求未变。
- **发布流程**：Stage 任务新增镜像冒烟验收，验收失败时不归集、不发布。
- 无数据迁移，无破坏性变化。
