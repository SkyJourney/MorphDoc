# Markdown 夹具

供渲染、预览、导出相关测试共用的 Markdown 输入。

## 目录

| 路径 | 说明 |
| --- | --- |
| `static/*.md` | 手写的静态夹具，每个聚焦一类输入 |
| `manifest.json` | 静态夹具清单：各夹具必须识别出的特性、必须不出现的特性、告警数或应抛出的错误 |
| `generate.mjs` | 确定性生成器：压力文档，以及 CRLF、BOM、纯空白等字节级变体 |

## 为什么部分输入不入库

仓库的 `.gitattributes` 设置了 `* text=auto eol=lf`，`git diff --check` 又会拒绝行尾空白，
因此 CRLF 换行、UTF-8 BOM、纯空白文档这类字节级输入无法稳定地保存为文件。它们由
`generate.mjs` 在测试时从 LF 夹具派生。

## 生成压力文档

```text
node fixtures/markdown/generate.mjs --out <目录> [--seed <整数>]
```

同一种子永远产出逐字节相同的内容，默认种子固定，测试失败时可以精确复现。

## 新增静态夹具

1. 把 `.md` 文件放入 `static/`，保持 LF 换行且不含行尾空白。
2. 在 `manifest.json` 中登记；清单与磁盘文件必须一一对应，否则测试失败。
3. 若引入了新的渲染器特性，`场景覆盖矩阵` 会要求至少有一个夹具覆盖它。

## 已知问题记录

测试文件末尾的 `已知问题` 用 `it.fails` 记录当前尚未修复的缺陷：缺陷存在时该用例
“通过”，缺陷被修复后它会失败，提示删除对应记录。
